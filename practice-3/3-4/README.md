# Диагностика сетевых соединений: Вариант 3

## Цель
Запустить TCP‑сервер на порту 8080, определить его PID и проверить связанные сетевые сокеты.

## Выполненные действия
1. Сервер запущен командой `nc -l -p 8080`, слушает порт 8080.
2. PID процесса `nc` определён с помощью `ps aux | grep nc`: **787**.
3. Состояние сокета проверено утилитой `lsof -i :8080`.

## Наблюдения
* Процесс `nc` (PID 787) успешно запущен и слушает порт 8080. В выводе `lsof` порт обозначен как `http-alt` — это общепринятое символическое имя для порта 8080 (alternative HTTP).
* PID совпадает в выводе `ps` и `lsof`.
* Сокет настроен на приём соединений со всех интерфейсов (`*`), что подтверждает доступность сервера извне.
* Состояние сокета — `(LISTEN)`, значит, сервер ожидает входящих подключений.
* Тип соединения — `TCP` по протоколу `IPv4`.

## Вывод
Утилиты `ps` и `lsof` позволяют быстро идентифицировать сетевой процесс и его состояние. `lsof -i` особенно полезен для диагностики: он связывает PID с сетевым портом, показывает состояние соединения и тип протокола. В данном случае подтверждено, что процесс `nc` с PID 787 корректно слушает порт 8080 и готов к приёму соединений.
